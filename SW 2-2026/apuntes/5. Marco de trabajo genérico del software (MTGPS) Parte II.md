## 1. Continuación del Marco de Trabajo de Desarrollo de Software
Continuamos hablando del **marco de trabajo para el desarrollo de software**, el cual está compuesto por 5 etapas:
1. Comunicación
2. Planeación
3. Modelado
4. Construcción
5. Despliegue
## 2. Etapa 4: Construcción
Esta etapa es relativamente corta porque solo habla de un tema principal: **la implementación más las pruebas**.
* **Implementación:** ¿Qué significa? En función a lo que vinimos hablando previamente, ¿qué hay que implementar? La solución descrita en el diseño. Al implementar, nos referimos a escribir el código.
* **El Código:** Aunque hoy en día escribir código ha bajado bastante de necesidad gracias a las herramientas automatizadas, siempre se requiere escribir código, ya sea de manera manual o automática.
### Selección de Lenguajes de Programación durante la Implementación
Cuando tenemos que seleccionar lenguajes de programación, debemos tomar en cuenta lo siguiente:
* Por lo general hacemos aplicaciones **web**, aplicaciones **móviles** o aplicaciones de **escritorio** (dependiendo del requerimiento).
* **¿En qué difiere una aplicación de escritorio y una aplicación web?** En la portabilidad. Una aplicación de escritorio no es portable porque requiere espacio en el sistema, es decir, se debe instalar un programa para que funcione en la computadora. En cambio, en la web simplemente entramos desde cualquier navegador.
### Traducción de Código (Compiladores vs. Intérpretes)
Lo que los humanos escriben (en PHP, C#, Python, etc.) no lo entiende la computadora directamente. Para que la computadora entienda, debemos traducirlo mediante el lenguaje de máquina.

Entre los lenguajes de programación existen **dos maneras de traducir el código**:
1. **Compilador**
2. **Intérprete**

* **Lenguajes con Compilador (ej. C#, C++):** Generan una aplicación portable. Se pasa de un código fuente a un código objeto, y finalmente a un código ejecutable que está enlazado a una arquitectura. Tenemos un archivo `.exe` que corre en el entorno para el cual fue elaborado. Antes de generar el código objeto, el compilador se asegura de que absolutamente todo el proyecto esté **libre de errores de sintaxis**.

* **Lenguajes con Intérprete (ej. PHP, Python):** No generan un código ejecutable independiente. Cada vez que corre el programa, se debe traducir y luego ejecutar.

* *Ventaja:* Son más portables.
* *Desventaja:* Si un programa en PHP o Python tiene un error de sintaxis oculto durante 10 años, el día que se ejecute la línea afectada, saltará el error. Con un compilador (como en C#), esto no pasa porque el compilador no te deja generar el ejecutable si hay errores.

## 3. Pruebas (Parte de la Construcción)
El propósito principal de las pruebas es **encontrar errores**. No hay ningún otro objetivo durante las pruebas que no sea ese.
* **¿Por qué debemos encontrar errores?** Si no los encontramos nosotros, los encontrará el usuario final, y eso es terrible para el negocio.
* **Pruebas Exhaustivas vs. Camino Básico:**
* Una prueba **exhaustiva** significaría probar el software de todas las maneras posibles para asegurar que está 100% libre de defectos, lo cual en la vida real **no es posible** porque tomaría muchísimo tiempo.
* Por ello, existe el método del **camino básico**, que simula al menos una vez cada posible recorrido que ocurra en un proceso.

## 4. Etapa 5: Despliegue
La última etapa es el **despliegue** (también conocido como lanzamiento, puesta en producción o publicación).
* **¿Qué se hace en el despliegue?** Se supone que todas las etapas del proceso de desarrollo ya han concluido, y se prepara la aplicación para que esté disponible para el usuario final.
* **Tareas principales:**
1. Asegurarse de tener las herramientas suficientes para desplegar la aplicación. Hoy en día esto se facilita mucho con el uso de la nube (Cloud).
2. Entrenar y capacitar a los usuarios para que sepan utilizar el sistema (manuales de usuario, tutoriales, etc.).
## 5. Mantenimiento del Software
Una vez que el software está en producción, no termina nuestra responsabilidad; entra en juego el **mantenimiento**. Existen cuatro tipos principales de mantenimiento:
1. **Mantenimiento Correctivo:** Corregir errores o fallas detectadas en el software.
2. **Mantenimiento Adaptativo:** Adaptar el software a nuevos escenarios, cambios en las políticas de negocio o actualizaciones en la infraestructura tecnológica.
3. **Mantenimiento Preventivo:** Introducir cambios o mejoras no porque el software tenga fallas actuales, sino para prevenir futuros errores o mejorar su rendimiento (Ejemplo histórico: el efecto Y2K o cambio al año 2000).
4. **Mantenimiento Perfectivo:** Introducir cambios porque podrían funcionar mejor
## 6. Gestión de Proyectos de Software
La gestión de proyectos abarca el rol del **Gestor de Proyectos** (Project Manager), quien se encarga de planificar, organizar, dirigir y administrar un proyecto de software para asegurar su éxito.
### Preguntas clave sobre un Proyecto:
1. **¿Qué hay antes de un proyecto?** Una `idea` y un `plan` de proyecto (o perfil de proyecto). No se puede llamar "proyecto" a algo que no tenga una planificación previa.
2. **¿Cuándo inicia un proyecto?** Cuando se `aprueba` un proyecto entre distintas opciones.
3. **¿Qué se hace durante un proyecto?** Ejecutar todo lo descrito en la planificación.
4. **¿Cuándo se dice que concluyó un proyecto?** Cuando se demuestra con éxito que se cumplieron todos los objetivos descritos en el plan.
5. **¿Cuándo se dice que se construyó un proyectó con éxito?** Cuando se cumple con el plan al 100%
