# Variables Importante de Estimaciones
- Costo: Es el costo por producir
- Tiempo: Tiempo de duración de producir
- Esfuerzo: Cantidad de recursos humanos expresado en personas/mes

a)
- Tamaño: Cantidad de funcionalidades del software (Se lo mira al ingeniero de requisitos, o los casos de uso para medir)

### `Objetivos del proyecto` 

 Se divide en 2:
	- Objetivo General: Lo que se va a hacer en el desarrollo (Empieza con `Desarrollar`)
	- Objetivo Especifico: Los objetivos tecnicos que tiene el software (No empiezan con `Desarrollar`)

###  `Rendimiento`
Es el tiempo de respuesta

**¿Qué hacemos para mejorar el tiempo de respuesta del software?**
- Optimar el código (consultas bases de datos)
- Gestión de cache
- Tareas en segundo plano 
- Monitorio del rendimiento
- Comprimir Assets (Imágenes, Iconos, Videos, etc...)
- Minimizar/Empaquetar el codigo de producción (frontend)

### `Fiabilidad` 
El la tolerancia del software a los fallos
Preguntas Clave:
**1. ¿Cuándo un software es fiable?**
	Cuando no falla.
**2. De ejemplos de fallas no demasiado criticas**
	Fallas en el cliente (frontend)
**3. De ejemplos graves que hagan perder dinero**
	Fallas en la logica de negocio
**4. De Fallas más graves**
	Fallas que pongas la vida del cliente en peligro (Ejemplo Ascender, Formula1)

> **Relación con las Estimaciones:** Cuanto más crítico sea un sistema ante posibles fallas, mayor será el esfuerzo, el tiempo y el costo de desarrollo, ya que se deben implementar fases exhaustivas de pruebas y simulaciones extremas para garantizar su robustez.

 
### `Restricciones` 
Son los límites o condiciones bajo las cuales debe operar y desarrollarse el proyecto. Se dividen en tres categorías principales:
**Existen Tres categorias de restricciones**
1. **Restricciones Técnicas:**
    - Obligaciones sobre el uso de tecnologías específicas impuestas por el cliente o el entorno (por ejemplo, desarrollar obligatoriamente bajo un lenguaje, framework o base de datos determinada, como usar _Clarion_ o tecnologías legadas).
2. **Restricciones Legales:**
    - Normativas jurídicas y fiscales que el software debe cumplir obligatoriamente por ley.
    - _Ejemplo clásico:_ Sistemas de facturación electrónica o cálculos de recursos humanos regidos estrictamente por leyes laborales del país (AFP, impuestos, etc.).
3. **Restricciones de Gestión / Recursos:**
    - Limitaciones de tiempo, presupuesto y personal asignado para ejecutar el proyecto.
	
### `Interfaces Externas` 
Hacen referencia a cómo el software se comunica e interactúa con su entorno, lo cual incluye:
- **Interfaces de Usuario (UI):** Diseño y adaptabilidad para la interacción humana.
- **Interfaces de Hardware:** Conexión con dispositivos externos, sensores o equipos especiales.
- **Interfaces de Software (APIs/Sistemas Externos):** Integración con servicios de terceros, pasarelas de pago o bases de datos externas.
