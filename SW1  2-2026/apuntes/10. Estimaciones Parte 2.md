## 1. Continuidad de la Planificación: Estimaciones
- **Objetivo central de las estimaciones:** Predecir y calcular de forma anticipada el tiempo, el costo y el esfuerzo necesarios para el desarrollo de un proyecto de software.
- Se debe estimar la métrica **PHU (Puntos de Historia de Usuario)** para cada historia de usuario definida en el backlog.
### ¿Cómo estimamos la cantidad de líneas de código para un proyecto nuevo?

| **Cantidad de Líneas** | **Caso / Escenario** |

| **Medio**              | Más Probable         |

## 2. Primera Forma: Puntos de Objeto (PO) y Reutilización
Método enfocado en medir el tamaño de la aplicación mediante la cuantificación de objetos del sistema (pantallas, informes, componentes de tercera generación - 3GL).


| **Tipo de Objeto**  | **Cuenta** | **Factor Simple** | **Factor Medio** | **Factor Avanzado** | **Total Ponderado**                |
| ------------------- | ---------- | ----------------- | ---------------- | ------------------- | ---------------------------------- |
| **Pantallas**       | 30         | 1                 | [2]              | 3                   | 60                                 |
| **Informes**        | 120        | 2                 | 5                | [8]                 | 960                                |
| **Componentes 3GL** | 18         | —                 | —                | [10]                | 180                                |
| **Total PO**        |            |                   |                  |                     | **1200** _(o 1230 según desglose)_ |

> $$TotalPonderado = Cuenta * FactorEscogido$$
### Cálculo de Puntos de Objeto Nuevos (PON)
Considera el porcentaje estimado de código reutilizado de proyectos anteriores:
$$PON = PO \times \left[\frac{100 - \text{\%Reutilizado}}{100}\right]$$
> _Ejemplo visto en clase:_
> Supongamos %Reutilizado = 30
> $$PON = 1200 \times \left[\frac{100 - 30}{100}\right] = 1200 \times 0.70 = 840 \text{ puntos}$$
## 3. Segunda Forma: Valor Esperado (VE — Técnica PERT)
Se utiliza para calcular una estimación ponderada combinando tres criterios (optimista, pesimista y más probable):
$$VE = \frac{\text{optimista} + 4 \times (\text{más probable}) + \text{pesimista}}{6}$$
## 4. Cálculo del Esfuerzo ($E$) y la Productividad (PROD)
El esfuerzo se calcula y se expresa en **personas/mes** ($\frac{\text{personas}}{\text{mes}}$) mediante la fórmula:

$$E = \frac{PON}{PROD}$$
### Tabla de Productividad (PROD)
Se evalúan los factores de proporción del equipo y del entorno:

| **Proporciones / Factores**        | **Baja** | **Baja-Media** | **Normal** | **Alta** | **Muy Alta** |
| ---------------------------------- | -------- | -------------- | ---------- | -------- | ------------ |
| **Capacidad y madurez del equipo** |          |                | ✅          |          |              |
| **Madurez del entorno**            |          | ✅              |            |          |              |
| **Valor de Productividad (PROD)**  | 4        | 7              | **13**     | 25       | 50           |

> _Ejemplo numérico aplicado:_
> $$E = \frac{PON}{PROD} = \frac{840}{20} = 42 \, \left(\frac{\text{personas}}{\text{mes}}\right)$$
## 5. Tercera Forma: COCOMO II (Modelo Constructivo de Costos)
- **Propósito:** Estimar la cantidad de esfuerzo expresada en personas/mes que se requiere para desarrollar un proyecto completo de software.
- Está fuertemente orientado a metodologías de desarrollo orientadas a objetos y lenguajes de alta generación (4ta generación), donde las interfaces (pantallas) y reportes implican menor cantidad de código detallado frente a los componentes lógicos de 3ra generación.
## 6. Cuarta Forma: La Ecuación del Software
- Consiste en otra alternativa metodológica estándar de la ingeniería de software orientada a estimar el esfuerzo y la planificación global del proyecto.
- **Nota importante:** Las **4 formas de estimación** vistas en clase (PO, VE, COCOMO II y Ecuación del Software) **deben ser aplicadas obligatoriamente al proyecto final de la materia**.

### ¿Qué es la Ecuación del Software?
En la gestión y estimación de proyectos de software, la **Ecuación del Software** (frecuentemente asociada al **Modelo de Putnam**) es un modelo empírico matemático que permite calcular el esfuerzo, el tiempo y el costo de desarrollo de un sistema.
Se basa en la relación entre:
- **El tamaño del software:** Estimado habitualmente en líneas de código (LOC) o puntos de función.
- **El tiempo de entrega (cronograma):** El plazo en meses o años establecido para finalizar el proyecto.
- **Una constante de productividad/tecnología:** Un factor que evalúa las herramientas, la experiencia del equipo y la complejidad del entorno de desarrollo.
Su fórmula general parte de la premisa de que el esfuerzo no es lineal, sino que sigue una curva de distribución de esfuerzo (curva de Putnam o Norden-Rayleigh), donde acelerar drásticamente un proyecto requiere un incremento exponencial de personal y recursos.
