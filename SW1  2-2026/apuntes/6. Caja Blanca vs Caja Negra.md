
Son `Pruebas o Enfoques`
#  `Caja Negra` (Black-Box)

- **Qué es:** Se evalúa la funcionalidad del software **desde el exterior**, analizando únicamente las **entradas (inputs) y salidas (outputs)** sin ver qué pasa por dentro.
- **Conocimiento requerido:** No se necesita saber programación ni tener acceso al código fuente.
- **Perspectiva:** Simula al usuario final, a un cliente o a un evaluador externo. 
- **Ejemplo:** Probar un formulario de inicio de sesión ingresando un correo y una contraseña para verificar si el sistema deja entrar al usuario o muestra un error adecuado.
- **Cuándo se aplica:** En pruebas de sistema, pruebas de aceptación de usuario (UAT) y validación funcional. 

# `Caja Blanca` (White-Box)
- **Qué es:** Se examina directamente el **código fuente, la lógica, la arquitectura y las estructuras internas** del programa.
- **Conocimiento requerido:** Requiere conocimientos sólidos de programación, algoritmos y diseño de software.
- **Perspectiva:** Es realizado por desarrolladores, ingenieros de control de calidad técnicos o especialistas en código.
- **Ejemplo:** Hacer pruebas unitarias a una función matemática específica para comprobar que todas las condiciones (if/else) y los bucles (loops) recorran las rutas lógicas esperadas.
- **Cuándo se aplica:** En fases tempranas de desarrollo y pruebas unitarias o de integración de código.
